# مراجعة النظام المالي — 16 نوفمبر 2026

> هذا سجل المراجعة قبل الإصلاحات. التغييرات والاختبارات اللاحقة موثقة في [تقرير الإصلاحات](REMEDIATION.md).

المراجعة كشفت **33 مشكلة مؤكدة: 15 عالية الخطورة (P1)، و18 متوسطة (P2)**. لا أوصي باعتماد مخرجات النظام المالية قبل معالجة أخطاء الأرصدة والرواتب والمرتجعات أدناه. هذه مراجعة للكود الحالي، وتشمل التعديلات المحلية الموجودة؛ لم تُطبّق إصلاحات على التطبيق ولم تتغير بيانات مالية حقيقية.

شملت المراجعة التحصيل، مراجع التحويل، المرتجعات، الفواتير، الضرائب، الورديات، الخزائن، العهد، التسليمات، الرواتب، الحضور، الإجازات، والتقارير. جرى فحص الصلاحيات ومسارات HTTP والمخطط، وتشغيل خدمات فعلية داخل اختبارات معزولة ببدائل لقاعدة البيانات. أمثلة المبالغ أدناه حالات اختبار، وليست معاملات العملاء.

P1 تعني خطأ في الأموال أو الرواتب أو عزل الفروع، أو تعطل مسار مالي رئيسي. P2 تعني خللاً في التشغيل أو التقارير أو إعادة المحاولة يحتاج إلى إصلاح قبل الاعتماد على المسار المتأثر. لا تعني هذه التصنيفات إثبات استغلال على بيانات الإنتاج.

## التحقق المنفذ

- `npm test`: نجحت **423 من 423**، دون اختبارات متخطاة. [السجل](offline-tests.log).
- شُغلت سكربتات الإثبات الأربعة المذكورة أعلاه بنجاح. نجاحها يعني أنها أثبتت السلوك الخاطئ المتوقع، ولا يعني إصلاحه. تستخدم السكربتات بدائل معزولة لقاعدة البيانات وعناوين اتصال وهمية؛ لم تُنفذ كتابات على قاعدة حقيقية.
- `npm run typecheck` و`npm run lint`: بلا أخطاء في التشغيل الجديد. [الأنواع](typecheck.log)، [lint](lint.log).
- `npx prisma validate`: المخطط صالح. ظهر تحذير Prisma عن إعداد قديم؛ لم يمنع التحقق. [السجل](prisma-validate.log).
- فحص حي للفهارس والصلاحيات عبر كتالوج PostgreSQL داخل معاملة قراءة فقط، دون قراءة سجلات العملاء أو تعديلها. [البيانات الوصفية](live-schema-metadata.json).

الفحص الحي أكد غياب قيد فريد لمرجع الدفع الخارجي. بعض الجداول المالية لا تفعّل RLS، لكن أدوار `anon` و`authenticated` لا تملك عليها صلاحيات SELECT أو INSERT أو UPDATE في الفحص؛ لذلك لم تُسجل كثغرة وصول مباشر مؤكدة. جداول المرتجعات والرواتب المفحوصة تفعّل RLS ولا تمنح تلك الصلاحيات أيضاً.

## ضوابط تعمل وحدود المراجعة

ظهرت ضوابط سليمة لحجز سقف المرتجعات، ومنع اعتماد المرتجع ذاتياً، وحماية فرع عمليات الكتابة، وإعادة نتيجة المرتجع المنفذ، وإرجاع المعاملة عند فشل سجل التدقيق. توجد أقفال لمسارات الوردية، وحماية للمبلغ النقدي في تنفيذ المرتجع، وقفل ومعالجة دقيقة للمبالغ وإعادة المحاولة في دفع الرواتب. لا تعني هذه الضوابط سلامة المسارات الأخرى المذكورة في التقرير.

إثباتا التزامن الخاصان بمرجع الدفع وحالة مراجعة الرواتب استخدما تداخلاً متحكماً فيه لخدمات التطبيق مع بدائل لقاعدة البيانات. لم يُنفذا كسباق حقيقي على PostgreSQL. لم تُجر مطابقة شاملة بين أرصدة الإنتاج والبنك والنقد الفعلي، أو تجربة مزود دفع حقيقي، أو اعتماد محاسبي أو ضريبي. لا يوجد بناء إنتاج جديد ضمن تحقق هذه المراجعة.

توجد نقاط تحتاج تحققاً إضافياً قبل تحويلها إلى مشاكل مؤكدة: فترات رواتب متداخلة، معالجة الموظفين المنقولين أو المنتهية خدمتهم تاريخياً، حدود العمل الإضافي، تكامل دفعات الرواتب مع دفتر النقد والبنك، واستكمال تسوية التحويلات البنكية. لا تدخل هذه النقاط في عدد 33.
